# 内网 / 受限电脑使用指南

> 针对「不能上 GitHub、可能没有 Node、可能是公司管控电脑」的情况。

---

## 一、最省事的用法：什么都不装

这个工具**不需要安装、不需要联网、不需要管理员权限**。

1. 把整个 `ledger-studio` 文件夹拷到那台电脑（U 盘 / 内网共享 / 微信传都行）
2. 双击 `index.html`
3. 直接用

就这样。所有 Excel 读写和规则计算都在浏览器里完成。

> 除非你在用 IE 或很老的浏览器，否则不用装任何东西。建议 Edge / Chrome。

### 如果需要「像个应用」

双击 `scripts/启动.bat`：

- 有 Node → 起本地服务并自动开浏览器（`http://127.0.0.1:5178`）
- 没 Node → 自动退化成直接打开 `index.html`

两种方式功能完全一致。

## 二、关于那台电脑上的「gitsource」

你说的这个名称有好几种可能，处理方式完全不同。**先确认是下面哪一种**：

### 情况 A：VS Code 里的「源代码管理」（Source Control）

如果看到的是一个侧边栏图标、里面有"更改/提交/推送"按钮，那就是 VS Code 内置的 Git 面板。

**用法**：

1. VS Code 打开 `ledger-studio` 文件夹
2. 左侧点"源代码管理"图标（分支样式的图标，快捷键 `Ctrl+Shift+G`）
3. 首次会提示"未检测到 Git 仓库"→ 点「初始化仓库」
4. 改完文件后，输入提交信息 → 点 ✓ 提交
5. 点 `...` → 推送到远程（需先配好 remote）

**局限**：VS Code 面板只能操作本地仓库和已配置的远程，不能帮你翻墙。如果那台机器连不上 GitHub，推送到 GitHub 依然会失败。

**但在内网场景下它很有用**：如果公司有内网 Git 服务，用 VS Code 面板提交 + 推送到内网仓库，就够了，不需要命令行。

---

### 情况 B：公司内网的 Git 服务（自建 GitLab / Gitea / 类似平台）

如果是网页打开的一个地址（比如 `http://git.公司域名/...`），那就是内网 Git 平台。

**这时候的正确姿势**：

1. 在**能上外网的机器**上，把项目推到 GitHub
2. 同一台机器上，加一个内网远端，再推一次：
   ```bash
   git remote add gitsource http://内网地址/团队/ledger-studio.git
   git push gitsource main
   ```
3. 到**内网机器**上：
   ```bash
   git clone http://内网地址/团队/ledger-studio.git
   ```
4. 以后更新：`git pull`

这样内网机器永远不需要碰 GitHub。

> 如果内网 Git 平台支持「镜像仓库 / Pull Mirror」，也可以配成自动从 GitHub 同步，但那通常要管理员权限。

---

### 情况 C：Git 客户端（Git for Windows / Git Bash）

如果那是个黑色命令行窗口或者一个叫 Git Bash 的程序，那就是 Git 本体。

**验证有没有**：命令行执行 `git --version`，能出版本号就行。

**基本操作就四条**：

```bash
git clone <仓库地址>      # 克隆
git pull                  # 拉更新
git add . && git commit -m "说明"   # 提交
git push                  # 推送
```

`scripts/更新.bat` 就是调 `git pull --ff-only`，所以只要 `git` 在 PATH 里，双击就能更新。

---

### 情况 D：公司的代码托管平台，名字里带 Git

有些企业平台叫「GitSource」「CodeSource」之类。处理方式和情况 B 一样。

---

### 不确定是哪一种怎么办

在那台电脑上执行这两条，把输出告诉我：

```bash
git --version
where git
```

- 有版本号 → 是情况 C（或 A 依赖它）
- 找不到 → 那台机器没装 Git，只能走离线包

## 三、完全不能访问外网时，怎么持续拿到新版本

见 `更新与镜像指南.md`，核心结论：

**这个项目离线更新的成本极低——把新文件覆盖过去就行，不需要装依赖、不需要迁移数据。**

操作就三步：

1. 外网机器上下载新版 zip
2. 拷进内网
3. 解压覆盖，重启

**注意保留**：`samples/` 目录下如果放了你自己项目的台账，覆盖前先备份。

## 四、内网环境的额外注意事项

| 事项 | 说明 |
| --- | --- |
| 浏览器策略 | 有些公司禁用了本地文件的 JS 执行。如果 `index.html` 打不开，改用 `启动.bat` 走 `http://127.0.0.1` |
| 摄像头/剪贴板权限 | 本工具不需要任何系统权限 |
| 文件下载位置 | 浏览器默认下载目录，可能在"下载"文件夹。建议改成桌面方便找 |
| 杀毒软件 | 纯 JS 文件，一般不会拦。`.bat` 可能被拦，可改用 `node server/server.js` 手动起 |
| 端口占用 | 默认 5178，被占用会自动 +1 重试，控制台会打印实际端口 |

---

## 五、把数据带出内网前

工具本身不含任何业务数据。但如果你需要把**检查报告**带给外部同事看，注意报告里会包含：

- 文件题名（可能含厂家名、设备型号）
- 归档人、检查人姓名
- 全宗号、单位名称

按你们的保密要求处理。工具不做任何脱敏。
