# 更新与镜像指南（网络受限环境专用）

> 目标：即使目标电脑**完全访问不了 GitHub**，也能拿到并持续更新这个工具。

---

## 一、先理解为什么这个项目离线更新特别容易

大部分项目离线更新很痛苦：要装依赖、要跑迁移、要改配置。

这个工具升级只需要一件事：**把新文件覆盖过去**。原因：

| 特性 | 带来的便利 |
| --- | --- |
| 零 npm 依赖 | 不用 `npm install`，不用管 lock 文件 |
| 纯静态资源 | 没有编译产物，覆盖即生效 |
| 无数据库 | 没有 schema 迁移 |
| 数据在浏览器内存 | 没有用户数据要备份 |

**所以最坏情况下的更新方式就是：复制粘贴。**

---

## 二、四条更新通道（按可用性从高到低）

### 通道 1：直连 GitHub（最优）

```bash
cd ledger-studio
git pull --ff-only
```

或者下载 Release 的 zip 解压覆盖。

**适用**：能访问 github.com 的机器。

---

### 通道 2：CDN 镜像（国内最常用）

GitHub 的仓库内容可以通过公共 CDN 分发，国内一般能通：

| 镜像 | 地址格式 | 说明 |
| --- | --- | --- |
| jsDelivr | `https://cdn.jsdelivr.net/gh/<用户>/<仓库>@<分支或tag>/<文件路径>` | 最稳，支持整包 |
| Fastly jsDelivr | `https://fastly.jsdelivr.net/gh/...` | jsDelivr 备用节点 |
| gh-proxy | `https://gh-proxy.com/https://github.com/<用户>/<仓库>/archive/refs/heads/main.zip` | GitHub 反代，下 zip 用 |

**下载整包**：

```bash
# 方式 A：jsDelivr 拿单文件（适合版本检查）
curl -O https://cdn.jsdelivr.net/gh/USER/ledger-studio@main/version.json

# 方式 B：gh-proxy 拿整包 zip
curl -L -o ledger-studio.zip https://gh-proxy.com/https://github.com/USER/ledger-studio/archive/refs/heads/main.zip
```

**应用内部的「检查更新」按钮已经内置了这条降级链**：先试 jsDelivr，失败自动换 raw.githubusercontent，再失败换 gh-proxy。

---

### 通道 3：npm 镜像（如果发布到 npm）

如果项目发布成 npm 包，国内镜像一般可用：

```bash
npm config set registry https://registry.npmmirror.com
npm pack ledger-studio          # 下载 tarball
tar -xzf ledger-studio-*.tgz
cp -r package/* /你的/ledger-studio/
```

**优点**：企业内网通常已经配好 npm 镜像（本次开发环境就是 `registry.npmmirror.com`，实测可用）。

---

### 通道 4：离线更新包（终极方案）

适用于**完全断网**的内网机器。

**在外网机器上**：

```bash
# 方式一：git 打成 zip
git archive --format=zip -o ledger-studio-v1.0.1.zip HEAD

# 方式二：直接压缩目录（去掉 .git 和 node_modules）
```

**拷贝到内网机器后**：

1. 关掉正在运行的程序
2. 解压覆盖到原目录（保留 `samples/` 里你自己的台账）
3. 重新双击 `启动.bat`

**校验是否更新成功**：

```bash
node scripts/print-version.js
# 输出：Ledger Studio LST-v1.0.1  (v1.0.1)  引擎 ENG-v1.0.0
```

或者打开页面看左上角的档号。

## 三、内网自建 Git 镜像（企业推荐）

如果公司有内网的 Git 服务（GitLab / Gitea / 自建），可以做成**双远端**：

```bash
# 一次性配置
git remote add origin  https://github.com/USER/ledger-studio.git     # 外网
git remote add mirror  http://内网git地址/team/ledger-studio.git      # 内网

# 平时推外网
git push origin main

# 外网机器上再同步到内网（在外网机器执行）
git push mirror main
```

**内网机器更新**：

```bash
git pull mirror main
```

这样内网机器永远只连内网地址，不碰 GitHub。

## 四、离线更新的实操脚本

`scripts/更新.bat` 已经处理了三种情况：

| 情况 | 行为 |
| --- | --- |
| 目录是 git 仓库且有 git 命令 | 执行 `git pull --ff-only` |
| 是解压安装包（无 `.git`） | 提示用 zip 覆盖 |
| 有 `.git` 但没装 git | 提示用 zip 覆盖 |

**为什么用 `--ff-only`**：防止本地有改动时产生 merge commit 把目录搞乱。拉不下来就明确失败，让用户走离线包，比自动 merge 更可控。

## 五、版本怎么对齐

三个地方会显示版本，任意一处即可确认：

1. 页面左上角：`LST-v1.0.0 · 引擎 ENG-v1.0.0`
2. 命令行：`node scripts/print-version.js`
3. 服务接口：`curl http://127.0.0.1:5178/api/version`

`version.json` 是给**外部更新检查**用的（静态托管，任何 CDN 都能取）。

## 六、常见故障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 「检查更新」一直转圈 | 所有源都不通 | 正常，离线环境就是会这样，走离线包 |
| `git pull` 报 `not a git repository` | 是 zip 解压的，没有 `.git` | 走离线包覆盖 |
| `git pull` 报冲突 | 本地改过文件 | `git stash` 后重试，或直接覆盖 |
| 更新后页面没变 | 浏览器缓存 | `Ctrl+F5` 强刷 |
| 页面白屏 | JS 没加载全 | F12 看 Console，通常是文件没覆盖全 |

## 七、发布检查清单（维护者用）

每次发版按这个顺序：

- [ ] `package.json` 的 `version` / `docNo`
- [ ] `assets/engine/engine.js` 的 `ENGINE_DOC_NO`
- [ ] `assets/app.js` 的 `APP_DOC_NO`
- [ ] `version.json` 的 `version` / `docNo` / `notes`
- [ ] `CHANGELOG.md` 追加一节
- [ ] `node test/run-tests.js` 全绿
- [ ] `git tag vX.Y.Z && git push origin --tags`
- [ ] GitHub Release 上传 zip
- [ ] 内网镜像同步（如启用）
