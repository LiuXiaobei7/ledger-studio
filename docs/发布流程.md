# 发布流程

本项目零依赖、纯静态，发布 = 把仓库推上去 + 打个标签 + 附一个 zip。

---

## 一、一键发布（推荐）

```bash
# Windows：双击
scripts\上传到GitHub.bat

# 或者命令行
node scripts/publish-to-github.js
```

脚本按顺序完成：

```
验证令牌 → 建仓库（不存在才建）→ 推送代码 → 打标签 → 建 Release → 上传 zip
```

### 令牌怎么拿

打开 https://github.com/settings/tokens/new?scopes=repo&description=ledger-studio

拉到底点 **Generate token**，复制那串 `ghp_...`（只显示一次）。
粘贴到脚本提示处即可。

也可以把令牌存成项目根目录的 `.github-token` 文件，之后不必每次输入。
该文件已在 `.gitignore` 中排除。

### 常用参数

| 参数 | 作用 |
| --- | --- |
| `--token ghp_xxx` | 直接指定令牌，不走交互 |
| `--repo 名称` | 仓库名，默认 `ledger-studio` |
| `--proxy http://127.0.0.1:端口` | 指定代理 |
| `--no-proxy` | 强制直连 |
| `--zip 路径` | 指定要上传的安装包 |
| `--keep-release` | 不覆盖已有的 Release 说明 |

### 发新版本前要改什么

1. `version.json` 里的 `version` 和 `docNo`（例如 `1.1.4` → `1.1.5`、`LST-v1.1.4` → `LST-v1.1.5`）
2. `package.json` 同步同样的版本号
3. `CHANGELOG.md` 顶部加一节 `## LST-v1.1.5 · 日期`
4. 打包 `dist/ledger-studio-v1.1.5.zip`

脚本会读 `version.json` 决定 tag 名，读 `CHANGELOG.md` 决定 Release 说明。

## 二、修改某个版本的更新说明

GitHub 上每个版本都有一页 Release，正文来自 `CHANGELOG.md` 里对应的小节。

**方式一：改文件后重跑（推荐）**

```bash
# 1. 编辑 CHANGELOG.md 里对应小节
# 2. 再跑一次
node scripts/publish-to-github.js
```

脚本发现该 tag 的 Release 已存在时，会用 **PATCH** 把说明更新成 CHANGELOG 的最新内容，
不会重复创建，也不会动已上传的附件。

好处是：说明同时存在于仓库里，别人 clone 下来能看到完整的版本历史。

**方式二：只改网页**

仓库 → Releases → 找到该版本 → 右上角铅笔图标 → 改完点 **Update release**。

> 如果你已经在网页上手改过，不想被脚本覆盖，加 `--keep-release`。

## 三、手动发布（不用脚本）

```bash
cd <项目目录>/ledger-studio

git remote add origin https://github.com/<用户名>/<仓库名>.git
git branch -M main
git push -u origin main

git tag -a v1.1.4 -m "LST-v1.1.4"
git push origin v1.1.4
```

推送时弹认证：

- 用户名：GitHub 用户名
- 密码：**不是账号密码**，要填 Personal Access Token（勾 `repo` 权限）

之后到仓库的 Releases 页面点 **Draft a new release**，选 tag、粘贴 CHANGELOG 内容、拖入 zip。

## 四、网络排查

命令行工具（`curl` / `git`）默认读 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量。
这两个变量指向的代理如果访问不了 GitHub，`git push` 会一直超时——**即使浏览器能正常打开 GitHub**，
因为浏览器走的是系统代理，两者不是一回事。

诊断：

```bash
curl -sS -m 10 -o /dev/null -w "%{http_code}\n" https://github.com
```

- `200` → 通了
- `000` → 超时

如果系统代理可用而环境变量指错了端口，可以只对 GitHub 单独指定（不影响其他仓库）：

```bash
git config --global http.https://github.com/.proxy http://127.0.0.1:<端口>
```

发布脚本不读环境变量，会自己依次探测常见本地代理端口（7897 / 7890 / 10809 …），
找到能连上 GitHub 的那个就用；也可以手动指定：

```bash
node scripts/publish-to-github.js --proxy http://127.0.0.1:<端口>
```

## 五、常见报错

| 提示 | 原因 | 处理 |
| --- | --- | --- |
| `令牌无效或已过期` | 复制错了，或已作废 | 重新生成，注意别带空格 |
| `连不上代理` / `请求超时` | 命令行访问不了 GitHub | 见上一节 |
| `创建仓库失败 403` | 令牌缺少 repo 权限 | 重新生成并勾选 `repo` |
| `同名附件已存在` | 该 zip 已上传过 | 正常，不重复上传 |
| `没有找到 Node.js` | 找不到 node 命令 | 在该目录开终端手动运行脚本 |

## 六、发布后启用应用内更新检查

仓库可用之后，改 `assets/notice.js`：

```js
mode: 'live',
endpoints: [
  'https://cdn.jsdelivr.net/gh/<用户名>/<仓库名>@main/version.json',
  'https://raw.githubusercontent.com/<用户名>/<仓库名>/main/version.json'
]
```

三条链路按顺序尝试，任一条通即可；全不通只提示「离线」，不影响任何功能。
