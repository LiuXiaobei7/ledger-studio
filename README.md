# 档案台账工作台 · Ledger Studio

> 一个纯本地运行的档案台账工具：**浏览器内完成检查与生成，文件不出本机，零安装可用**。

**档号：LST-v1.1.0** · 引擎：ENG-v1.0.0 · 补录：BFILL-v1.0.0

---

## 这是什么

工程档案归档时，需要产出两本 Excel：《文件台账》（74 列）与《案卷台账》（60 列）。
这两本台账字段多、规则杂、相互联动，人工核对一本 70 件的台账要花两三个小时，还容易漏。

这个工具把归档规范固化成一套可执行的规则，做两件事：

| 能力 | 说明 | 状态 |
| --- | --- | --- |
| **生成** | 只填 8 项要素（案卷档号、案卷题名、脊背宽度、文件题名、文件编号、文件日期、责任者、页数），自动补齐其余 60 余个字段，产出可直接导入的两本台账 | 实验 |
| **检查** | 读入两本台账，逐条校验 25 条规则，输出带行号/列名的问题报告，并生成排版规范的副本 | 稳定 |
| **PDF 补录** | 从 PDF 文字层推测缺失或错位的「文件编号 / 文件日期」，只补少量缺失 | 实验 |
| **参数配置** | 固定值基准、分类号映射、项目全称可视化编辑，检查与生成共用，保存在本机 | 稳定 |

生成与检查互为逆过程：**生成的结果必须能通过检查**，这条闭环本身就是测试用例。

> 页签顺序按实际工作流排：**先生成 → 后检查**。生成属实验功能，产出后务必人工复核。

## 快速开始

### 方式一：双击打开（零安装）

```
双击 scripts/启动.bat
```

如果本机没有 Node.js，脚本会自动改用浏览器直接打开 `index.html`——**功能完全一致**，因为所有计算都在浏览器里完成。

### 方式二：本地服务

```bash
npm start            # 默认 http://127.0.0.1:5178/，自动打开浏览器
npm start -- --port 8080
```

只有一个 Node 内置模块写的静态服务，**没有任何 npm 依赖**。

### 方式三：直接打开 HTML

双击 `index.html` 即可。不需要联网，不需要装任何东西。

## 为什么是「纯前端」

这类工具最容易踩的坑是把文件传到服务器。档案台账含全宗号、单位名称、人员姓名，属于不适合外传的数据。

所以架构上做了个硬决定：**没有任何后端处理逻辑**。

- Excel 读写用 ExcelJS 在浏览器内完成
- 规则引擎是纯函数，无副作用
- 本机服务只做静态文件分发，不接收文件、不落盘
- 断网状态下功能完全正常

代价是 PDF 页数只能靠浏览器端估算，精确校验需要 CLI 版。这个取舍在 `docs/` 里有说明。

## 启动公告与版本检查

每次打开页面会：

1. **弹出公告**（顶部「公告」按钮可再次查看）
2. **自动检查版本**，有新版本时顶部徽标变成「有新版本」

当前 `assets/notice.js` 的 `mode` 是 `demo`，不会联网，直接展示内置的示例公告与版本信息——因为项目还没发布到 GitHub。
发布后把它改成 `live`，并把 `endpoints` 里的 `USER` 换成实际用户名，就会走真实的三级降级链：

```
jsDelivr → raw.githubusercontent.com → gh-proxy
```

任一条通就行；全不通也只是提示「离线」，不影响任何功能。

## 参数配置

「参数配置」页可以改三类东西，**检查与生成共用同一份配置**：

| 组 | 内容 |
| --- | --- |
| 项目全称 | 校验题名前缀、生成时补全题名 |
| 固定值基准 | 文件台账 11 列 / 案卷台账 17 列，换项目时改这里 |
| 分类号映射 | 分类号 → 分类名称 / 保管期限 / 保管期限代码 |

配置存在浏览器 `localStorage`（键 `ledger-studio-cfg-v1`），换电脑或换浏览器不会同步。
需要跨机器复用时点「导出 JSON」，到另一台机器「导入 JSON」即可。

> 注意：`localStorage` 按域名隔离。用 `http://127.0.0.1:5178` 打开和直接双击 HTML（`file://`）是两套存储，配置不互通。建议固定用一种方式。

## PDF 源补录（实验）

**做什么**：读 PDF 的文字层，推测哪些文字是文件编号、哪些是 8 位日期，补进台账里缺失或错位的字段。

**输入**：PDF 所在文件夹 + 需补录的文件台账（.xlsx）

**启发式**：

| 字段 | 识别方式 |
| --- | --- |
| 文件日期 | 8 位连续数字、`2025-03-25`、`2025年3月25日`、`二〇二五年三月二十五日`；排除非法日期；按出现次数与「签发/出厂/检验/日期」等关键词邻接程度打分 |
| 文件编号 | 关键词邻接（编号/证号/批号/NO.）权重最高；其次字母+数字混合 token（如 `TKG711510002`）；再次 10 位以上纯数字。**排除** 8 位日期、档号、短页码 |

**错位检测**：日期格里放的不是日期、编号格里放的是日期，都会标出来并给出交换建议。

**置信度**：高 / 中 / 低，低于「自动采纳门槛」的只列出来供人工判断，不写进台账。

**限制（重要）**：

- 只处理**少量**缺失。整本台账同类文件都缺编号或日期，这个功能补不出来
- PDF 必须**有文字层**。扫描件（纯图片）读不出任何内容，会明确标为「无文字层」
- 页数是浏览器端估算，同一份 PDF 在不同版本下可能差几页
- **必须通过本地服务运行**（`启动.bat` / `npm start`）。`file://` 直接打开时浏览器禁止 Web Worker，功能不可用

**输出**：`原文件名_已补录.xlsx`，已应用排版，逐条核对后再用。

## 规则一览

| 组 | 规则 |
| --- | --- |
| F1–F4 | 固定值列一致性、单本内一致性、文件档号构成与唯一性、卷内序号连续 |
| F5–F8 | 文件日期与年度、页数等式、图纸类复核提醒 |
| F9–F11 | 文件题名格式、PDF 文件名、PDF 页数 |
| F12 | 日期/编号为空（允许项，仅记录） |
| J1–J4 | 案卷固定值列、单本一致性、案卷档号构成、案卷号流水 |
| J5–J8 | 四日期倒推工作日链、归档当日提醒、正副本数 |
| J7/J9 | 可疑案卷识别与脊背宽度复核、扫描概览 |
| X1–X4 | 归档日期联动、案卷年度联动、卷号存在性、无法校验项 |

界面里「规则清单」标签页可以看到每条规则的完整说明。

### 关于「可疑案卷」

脊背宽度不逐卷提醒——那等于没提醒。只对四类可疑卷报出来：

1. **件数离群**：同类卷中位数 ≥4 件时，本卷件数不到中位数的 60%
2. **单据类型离群**：卷内 ≥5 件时，某类单据只有 ≤2 件且占比 ≤25%（一堆逆变器资料里混进一张保修卡）
3. **子阵覆盖不全**：同类卷普遍覆盖多个子阵，本卷只覆盖更少
4. **页数与脊背不匹配**：按「每毫米承载页数」比较，本卷明显低于同类最优者（差 3 倍以上）
